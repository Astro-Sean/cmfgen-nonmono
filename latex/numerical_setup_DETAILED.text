S. Brennan

Max Planck Institute for Astrophysics, Karl-Schwarzschild-Str. 1, 85741 Garching, Germany

Numerical Setup

This section describes the numerical methods and model configuration used to
simulate the double-explosion scenario consisting of a Type IIb supernova
(SNA) and a subsequent H/He shell ejection into the SNA ejecta (SNB).
The modelling pipeline couples the multi-group radiation hydrodynamics code
STELLA with the non-LTE
radiative transfer code CMFGEN
 for spectral synthesis at selected epochs.

Overview of the Modelling Pipeline

The simulation proceeds in two stages.  In the first stage (SNA), a
stripped-envelope progenitor is exploded as a Type IIb supernova and evolved
with STELLA from shock breakout (SBO) through the radioactive-decay-powered
light-curve phase.  A snapshot at 30d post-SBO is extracted and
remapped onto a CMFGEN depth grid for non-LTE spectral synthesis.  The SNA
ejecta is then homologously evolved to late times (400d) to serve as
the circumstellar medium (CSM) for the second stage.

In the second stage (SNB), a H/He shell is placed at the centre of the
homologously expanded SNA ejecta and launched at 5000 into the
surrounding CSM.  STELLA evolves the shell-CSM interaction, and a snapshot
at 20-40d after shell launch is extracted for CMFGEN spectral
synthesis.

The entire pipeline is orchestrated by a single workflow manager
(runmodelgrid.py) that handles progenitor conversion, STELLA
job submission, snapshot extraction, CMFGEN grid generation, and
dependency-chained spectral synthesis jobs on a high-performance computing
(HPC) cluster.

STELLA Radiation Hydrodynamics

STELLA solves the
one-dimensional Lagrangian radiation hydrodynamics equations with
multi-group grey radiative transfer in the homologous comoving frame.  The
code employs a variable Eddington factor closure and treats radiation
transport in two regimes: a diffusion approximation for the optically
thick interior () and a ray-by-ray (characteristic) method
for the optically thin outer layers ().  The boundary
between these regimes, , is determined at each timestep by searching

STELLA Evolution of the Interaction

STELLA evolves the SNB model for 45d from the shell launch time.
The H/He shell, moving at 5000, drives a strong forward shock
into the slower CSM (-), while a reverse shock
propagates back into the shell.  The shock interaction converts kinetic
energy into radiation, producing the interaction-powered luminosity that
characterises Type IIn supernovae.

The artificial viscosity is set to  (higher than the SNA
value of 2-4 for a standard thermal-bomb explosion) to stabilise the
GEAR solver across the strong velocity reversal at the shell-CSM
interface.  The GEAR method is set to 3 (GEAR+BGH) for improved stability
in the stiff interaction system.  No  is included in the SNB model;
the luminosity is entirely interaction-powered.  The maximum timestep is
limited to 3600s (1h) to resolve the early shock interaction phase.

CMFGEN Non-LTE Spectral Synthesis

STELLA-to-CMFGEN Conversion

At selected epochs (30d post-SBO for SNA; 20-40d post-launch for
SNB), a snapshot is extracted from the STELLA .swd output file
and converted to CMFGEN's SNHYDRODATA format by the script
convertstellaswdtocmfgen.py.  The conversion performs
the following steps:


    Epoch selection: The STELLA epoch closest to the
    requested snapshot day (within a tolerance of 2d) is selected.
    If no STELLA epoch is available (e.g. for late-time snapshots beyond

    remapped onto a CMFGEN depth grid using an adaptive algorithm that
    concentrates zones in regions of steep gradients (ionisation fronts,

CMFGEN Configuration and Convergence Strategy

CMFGEN computes
non-LTE level populations and emergent spectra for a spherically symmetric
supernova atmosphere.  The code solves the radiative transfer equation in
the Sobolev approximation with continuum opacities treated in the
co-moving frame, and iterates the statistical equilibrium equations
coupled to the radiative transfer via an accelerated Lambda iteration
(ALI) scheme.

Velocity law and grid.
For both SNA and SNB, the velocity law is set to
VELLAW=12, which reads the actual (non-homologous)
velocity profile from the SNHYDRODATA input rather than
fitting a homologous  relation.  This is essential for the
SNB model, where the shell-CSM velocity reversal produces
 regions that a homologous fit cannot represent.  The
VELLAW=12 routine includes a protective clamp that sets

line optical depth denominator  from approaching
zero.  Empirical tests confirm that removing this clamp causes
catastrophic divergence of the Ng acceleration extrapolation, even though
the Sobolev guard

well-defined for all finite .

Solver configuration.
The depth-coupling solver is set to TRIDIAG
(NUMBNDS=3), which allows inter-depth error propagation
via a tridiagonal band matrix.  This is required for models with
non-monotonic velocity (), where the diagonal-only
(DIAG) solver cannot capture the inter-depth coupling introduced
by the velocity reversal.  The formal solution uses
NTYPE=NONJ with USELAMES=T, which
sets the mean intensity  to the formal-solution value 
and bypasses the moment equations, improving stability for models with
large velocity gradients.

Iteration strategy.
The convergence strategy employs alternating LAMBDA and Boltzmann
Acceleration (BA) iterations, controlled by the following VADAT
parameters:

    DONG=F: Ng acceleration is
    disabled.  While Ng acceleration can speed convergence for well-behaved
    models, it destabilises trace species (e.g. Fe iv,
    Fe v) at ionisation fronts by extrapolating across
    oscillatory population changes, leading to divergence of up to
     in the maximum correction.
    DOAV=T: Population averaging
    (AVEFLIPS) is enabled to damp oscillating populations
    between LAMBDA iterations.  A source-code patch was applied to allow
    AVEFLIPS to fire during continuous LAMBDA iterations
    (DOLAMIT=T), which was previously blocked by a
    condition that required MAINCOUNTER  LASTLAMBDA +
    NUMOSCAV + 2 - a condition that is never satisfied when every
    iteration is a LAMBDA iteration.
    MAXLAM=: The maximum fractional population
    change per LAMBDA iteration is capped at , with
    LAMSCALEOPT=LIMIT applying a proportional limiter to
    trace species.
    MAXLIN=3: The maximum number of linearisation
    steps per BA iteration is limited to 3 (reduced from the manual
    default of 10) for cold-start stability, as the BA solve can produce
    extreme corrections when the initial LTE populations are far from the
    converged solution.
    BACHKFAC=0.05: The BA matrix is held fixed
    when the maximum population correction falls below 5%, avoiding
    unnecessary matrix recomputations.
    METHOD=ZERO: The trapezoidal optical-depth
    integration method is used, as recommended by the CMFGEN
    documentation for models with convergence difficulties.
    FIXT=T: The temperature is fixed to the
    hydrodynamic (STELLA) value at all depths throughout the iteration,
    preventing CMFGEN from solving for temperature and using the
    physically consistent hydrodynamic temperature instead.

Species selection.
The atomic model includes H i, He i, O i,
Si i-ii, Ca i-ii, and Fe i-iii as the
primary spectral-line species.  High-ionisation iron species
(Fe iv, Fe v) are removed for the 30d SNA snapshot,
as their ionisation potentials ( and 77eV) are far above
the maximum ejecta temperature (K at 30d),
making their NLTE populations  (set by photoionisation
from the photospheric radiation field) and introducing 
trace-species noise into the convergence.  Similarly, C ii is
reduced to ground-state-only (ISF=1,1,1) for models with
near-zero carbon abundance (), as 8 NLTE levels with
zero abundance drove  fractional population cascades.

Spectral synthesis.
Once the level populations have converged, CMFGEN computes the emergent
spectrum via a formal solution of the radiative transfer equation on a
fine frequency grid spanning 900-28000 (covering the optical
through mid-infrared for JWST MIRI comparison).  The spectrum includes
line blanketing from all included species, continuum opacities
(bound-free, free-free, electron scattering), and the diffuse emission
from the SN ejecta.  An observed-frame spectrum is produced by applying
the cosmological redshift and distance modulus appropriate to the target
SN.

Computational Infrastructure

All simulations are performed on the MPCDF Viper HPC cluster using SLURM
job scheduling.  STELLA runs on a single node with 16GB memory and a
24h wall-time limit.  CMFGEN runs use the same resources, with
dependency-chained INITSTABLEFINAL or single-FINAL
configurations.  The workflow manager runmodelgrid.py
handles automatic job cancellation of previous runs, directory cleanup,
VADAT/MODELSPEC regeneration from YAML configuration, and consistent
validation of solver parameters across all model components.
